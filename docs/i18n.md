# Interface languages

The interface supports English (`en`) and Simplified Chinese (`zh-CN`) through
Vue I18n's Composition API. English is the default and missing-message fallback.

## Selection and persistence

On startup, `src/i18n/index.ts` first reads `wallpaper-web.locale` from
`localStorage`. Only the exact supported values are accepted. Without a valid
saved selection, it checks `navigator.languages` in preference order, falling
back to `navigator.language` if the list is empty. English variants map to `en`;
Chinese variants map to `zh-CN` (including Traditional Chinese browser preferences,
because only Simplified Chinese is currently available). Unsupported preferences
are skipped; if none match, the interface uses English.

The native selector at the top right lists only **English** and **简体中文**.
Changing it updates the interface immediately and saves the manual choice.
There is no automatic-mode option. Browser preferences are read at startup, not
continuously observed. Storage read/write failures do not prevent the interface
from working; a choice that cannot be saved lasts for the current visit.

Locale changes update the document's `lang`, title and description, date labels,
loading/error/empty states, download feedback and accessibility labels. They do
not change the URL, refetch metadata, reset appended cards, replace API content,
or close an open viewer. The document update watcher belongs to `App.vue` and
stops when the app unmounts. While the native modal is open, the header is inert;
users close the viewer before using its language selector.

## Translation ownership

Maintain English messages in `src/i18n/locales/en.ts` and matching Chinese
messages in `src/i18n/locales/zh-CN.ts`. Messages are grouped by feature and loaded
with the app. Add or change both dictionaries in the same feature change, and
review translations as source code. The Chinese dictionary is checked against
the English shape by TypeScript; tests also compare keys and interpolation
parameters, reject blank messages, and verify English fallback behavior.

Use stable semantic keys, whole sentences and named interpolation parameters.
Use Vue I18n plural messages for English counts rather than concatenating words.
Render all translated and API content as text, never HTML. Vue I18n does not
automatically translate messages or fetch translations from an external service.

`useLocalization()` exposes translation, selection and presentation helpers.
Persist status codes/counts rather than translated strings, so existing download
feedback and append announcements update when the locale changes.

Wallpaper titles and copyright text remain in their source language. The API
service normalizes a missing/blank title to an empty string. Components use
`wallpaperTitle()` to generate a localized date-based fallback, including image
alt text and accessible button labels. API errors remain language-independent
classifications and are translated by presentation components.

## Dates and fonts

`formatDate()` formats source calendar dates with `Intl.DateTimeFormat` using
the active interface locale and an explicit UTC time zone. This avoids shifting
the displayed day in other browser time zones. API query values, URL parameters,
`datetime` attributes and download filenames retain `YYYY-MM-DD`. Native date
input rendering and its picker can follow browser/OS conventions independently
of the chosen interface language.

The existing WenKai assets cover the original font's complete character map;
new text can use the full font chunks. Regenerating the priority subset is an
optional optimization described in README, not a requirement to display these
languages. Keep the current font license and assets.

## Verification

- `npm run test:coverage`: locale matching, saved/invalid/blocked storage,
  dictionary parity, interpolation, English plurals/fallback, UTC dates, original
  content, reactive metadata and native selector interactions. The i18n modules
  and language selector must reach 100% statements, branches, functions and lines;
  Vite+ enforces these thresholds, including in CI. Dictionaries contain static
  data and are verified by the parity tests rather than executable counters.
- `npm run test:e2e`: production-preview Chromium checks for browser defaults,
  English fallback, manual preference persistence, state/request preservation,
  translated download feedback, focus restoration and both-language layouts.
- `npm run check` and `npm run build`: formatting/lint, strict types and bundling.

The established archive E2E suite explicitly uses a Chinese browser locale;
language tests also use English and unsupported browser preferences. API/image
boundaries are mocked only in tests. They do not verify a live backend or external
image availability.
